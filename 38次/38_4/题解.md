# 题解

这道题的难点在于将一个复杂的字符串匹配问题，转化为一个可以进行数学优化的动态规划（DP）模型。要拿到满分，你需要掌握**有限状态机（Automaton）**、**矩阵快速幂（Matrix Fast Exponentiation）**以及对**分段处理**的深刻理解。

以下是该题的详细逻辑解析：

### 1. 核心思路：状态机 DP

题目要求计算满足条件的字符串数量。条件是：**至少存在一个 `ccf` 在 `cspark` 的左侧**。
我们可以设计一个自动机，用来描述我们目前“匹配到了哪一步”。我们将状态分为三大类，细分为 10 个具体状态：

#### 第一阶段：寻找第一个 `ccf`
*   **状态 0**：初始状态，什么都没匹配到。
*   **状态 1**：匹配到了 `c`。
*   **状态 2**：匹配到了 `cc`。
*   **状态 3**：**成功匹配到第一个 `ccf`**。此时我们开始寻找 `cspark`。

#### 第二阶段：已找到 `ccf`，寻找随后的 `cspark`
*   **状态 4**：匹配到了 `ccf` ... `c`。
*   **状态 5**：匹配到了 `ccf` ... `cs`。
*   **状态 6**：匹配到了 `ccf` ... `csp`。
*   **状态 7**：匹配到了 `ccf` ... `cspa`。
*   **状态 8**：匹配到了 `ccf` ... `cspar`。

#### 第三阶段：大功告成
*   **状态 9**：**成功匹配到了 `ccf` 及其后的 `cspark`**。这是一个“吸收态”，一旦进入此状态，后面无论填什么字符，该字符串都符合要求。

### 2. 构建转移矩阵 (Transition Matrix)

对于每一个状态 $i$ 和每一个可能的字符 $c \in \{'a' \dots 'z'\}$，我们计算它会转移到哪个新状态 $j$。
例如：
*   在状态 2 (`cc`) 时，如果遇到字符 `'f'`，转移到状态 3；如果遇到 `'c'`，保持在状态 2；否则回到状态 0。
*   在状态 8 (`ccf...cspar`) 时，如果遇到 `'k'`，转移到状态 9。
*   在状态 9 时，遇到任何字符都留在状态 9（有 26 种路径）。

我们将这些转移关系总结成一个 $10 \times 10$ 的矩阵 $M$，其中 $M_{j,i}$ 表示从状态 $i$ 经过一个字符转移到状态 $j$ 的方案数。

### 3. 处理井号 (`#`) 的分段效应

井号是固定位置的，且井号不是字母。这意味着：
*   **`ccf` 或 `cspark` 不能被井号打断**（例如 `cc#f` 不算 `ccf`）。
*   井号会将字符串分成 $m+1$ 个纯字母段。

**关键点：** 当遇到一个井号时，我们目前的“部分匹配进度”会丢失，但“阶段性成果”会保留：
*   如果你处于状态 0, 1, 2（还没找到 `ccf`），碰到 `#` 后，进度重置为 **状态 0**。
*   如果你处于状态 3, 4, 5, 6, 7, 8（已经找到 `ccf`，但在找 `cspark`），碰到 `#` 后，进度重置为 **状态 3**（因为 `ccf` 已经找到了，不能被抹除）。
*   如果你处于状态 9（已经成功），碰到 `#` 后，依然处于 **状态 9**。

### 4. 矩阵快速幂优化

由于总长度 $n$ 高达 $10^9$，我们不能逐个字符转移。
对于长度为 $L$ 的纯字母段，其转移过程可以用矩阵的幂 $M^L$ 来表示。
$V_{after\_segment} = M^L \times V_{before\_segment}$

**算法流程：**
1.  计算所有井号之间的字母段长度 $L_1, L_2, \dots, L_{m+1}$。
2.  初始状态向量 $V = [1, 0, 0, \dots, 0]^T$（表示初始处于状态 0 的概率为 1）。
3.  对于每一段长度 $L_i$：
    *   利用**矩阵快速幂**计算 $M^{L_i} \times V$。
    *   **处理井号**：根据上述第 3 点的逻辑调整 $V$（将 $V_{1,2}$ 累加到 $V_0$ 后清零，将 $V_{4..8}$ 累加到 $V_3$ 后清零）。
4.  最后 $V$ 向量中的第 9 位（$V_9$）即为答案。

### 5. 满分技巧与复杂度分析

*   **复杂度**：矩阵大小为 $K=10$。每次快速幂复杂度 $O(K^3 \log n)$。总共有 $m$ 段，复杂度 $O(m \cdot K^3 \log n)$。
*   **优化**：在实际测试中，$m$ 很大 ($10^6$)，如果对每一段都跑一遍快速幂会超时。由于很多段的长度 $L$ 可能相同，可以使用 `std::map<long long, Matrix>` **缓存**已经计算过的矩阵幂结果。
*   **去重**：这种 DP 方法天然地避免了重复计数问题。因为它统计的是“在这一刻第一次进入状态 9”的所有可能路径，每个合法字符串只会被统计一次。

### 总结
这道题的本质是**在给定约束（井号）下的自动机路径计数**。通过矩阵快速幂，我们将线性时间的 DP 压缩到了对数时间，从而处理了 $10^9$ 的超大规模数据。

## 代码

为了拿到满分，我们需要使用**矩阵快速幂优化动态规划**。

### 核心逻辑重申：
1.  **状态定义**：我们定义 10 个状态来记录当前匹配的进度（0-2 找 `ccf`，3-8 已找到 `ccf` 并在找 `cspark`，9 大功告成）。
2.  **分段处理**：由于 $n=10^9$ 且井号位置固定，我们将字符串切分为由井号分隔的多个纯字母段。
3.  **矩阵加速**：每一段字母段的转移通过矩阵快速幂完成。
4.  **记忆化**：使用 `std::map` 缓存相同长度段的矩阵结果，应对 $m=10^6$ 时段数过多的情况。

以下是带有详细中文注释的满分思路代码：

```cpp
#include <iostream>
#include <vector>
#include <map>

using namespace std;

typedef long long ll;
const int MOD = 998244353;
const int SIZE = 10; // 自动机状态总数：0-9

// 矩阵结构体，用于矩阵快速幂
struct Matrix {
    ll mat[SIZE][SIZE];
    Matrix() {
        for (int i = 0; i < SIZE; i++)
            for (int j = 0; j < SIZE; j++) mat[i][j] = 0;
    }
    // 返回单位矩阵
    static Matrix identity() {
        Matrix res;
        for (int i = 0; i < SIZE; i++) res.mat[i][i] = 1;
        return res;
    }
    // 矩阵乘法
    Matrix operator*(const Matrix& other) const {
        Matrix res;
        for (int i = 0; i < SIZE; i++) {
            for (int k = 0; k < SIZE; k++) {
                if (mat[i][k] == 0) continue; // 优化：跳过零项
                for (int j = 0; j < SIZE; j++) {
                    res.mat[i][j] = (res.mat[i][j] + mat[i][k] * other.mat[k][j]) % MOD;
                }
            }
        }
        return res;
    }
};

// 矩阵快速幂：计算 M^exp
Matrix matrix_pow(Matrix a, ll exp) {
    Matrix res = Matrix::identity();
    while (exp > 0) {
        if (exp % 2 == 1) res = res * a;
        a = a * a;
        exp /= 2;
    }
    return res;
}

// 构造基础转移矩阵（代表输入一个任意字母 a-z 时的状态转移计数）
Matrix build_base_matrix() {
    Matrix M;
    // 状态定义：
    // 0:"", 1:"c", 2:"cc" -> 匹配 ccf
    // 3:"找到ccf", 4:"+c", 5:"+cs", 6:"+csp", 7:"+cspa", 8:"+cspar" -> 匹配 cspark
    // 9:"达成目标" (ccf 且随后有 cspark)
    
    for (int s = 0; s < SIZE; s++) {
        for (char c = 'a'; c <= 'z'; c++) {
            int next_s;
            if (s == 9) { // 状态9是吸收态，一旦达成，后面填什么都还是达成
                next_s = 9;
            } else if (s < 3) { // 寻找 ccf 阶段
                if (c == 'c') next_s = (s == 0 ? 1 : 2);
                else if (c == 'f' && s == 2) next_s = 3;
                else next_s = 0;
            } else { // 已经有 ccf，寻找 cspark 阶段
                if (c == 'c') next_s = 4; // 任何时候遇到 c 都可以作为 cspark 的开始
                else if (c == 's' && s == 4) next_s = 5;
                else if (c == 'p' && s == 5) next_s = 6;
                else if (c == 'a' && s == 6) next_s = 7;
                else if (c == 'r' && s == 7) next_s = 8;
                else if (c == 'k' && s == 8) next_s = 9;
                else next_s = 3; // 没匹配上，回到“已有ccf”的基础状态
            }
            M.mat[next_s][s]++;
        }
    }
    return M;
}

int main() {
    ios::sync_with_stdio(false); cin.tie(0);

    ll n;
    int m;
    cin >> n >> m;

    vector<ll> pos(m);
    for (int i = 0; i < m; i++) cin >> pos[i];

    // 计算段长度：井号把字母切成 m+1 段
    vector<ll> segments;
    if (m == 0) {
        segments.push_back(n);
    } else {
        segments.push_back(pos[0] - 1); // 第一段井号前的字母
        for (int i = 0; i < m - 1; i++) {
            segments.push_back(pos[i+1] - pos[i] - 1); // 井号之间的字母
        }
        segments.push_back(n - pos[m-1]); // 最后一段井号后的字母
    }

    Matrix base = build_base_matrix();
    map<ll, Matrix> cache; // 缓存矩阵幂，应对段数极多且长度重复的情况

    // 初始状态向量：只有状态0为1（空串）
    ll V[SIZE] = {0};
    V[0] = 1;

    for (int i = 0; i < segments.size(); i++) {
        ll L = segments[i];
        if (L > 0) {
            if (cache.find(L) == cache.end()) {
                cache[L] = matrix_pow(base, L);
            }
            Matrix& ML = cache[L];
            
            ll next_V[SIZE] = {0};
            for (int r = 0; r < SIZE; r++) {
                for (int c = 0; c < SIZE; c++) {
                    next_V[r] = (next_V[r] + ML.mat[r][c] * V[c]) % MOD;
                }
            }
            for (int j = 0; j < SIZE; j++) V[j] = next_V[j];
        }

        // 处理井号：井号打断了所有正在进行的匹配（状态重置）
        // 只有到了最后一个字母段（没有后续井号了）才不执行这个逻辑
        if (i < m) {
            ll next_V[SIZE] = {0};
            // 还没找到 ccf 的（状态 0,1,2），遇到井号全部打回状态 0
            next_V[0] = (V[0] + V[1] + V[2]) % MOD;
            // 已经找到 ccf 还没找全 cspark 的（状态 3-8），遇到井号打回状态 3（ccf依然有效）
            next_V[3] = (V[3] + V[4] + V[5] + V[6] + V[7] + V[8]) % MOD;
            // 已经达成的（状态 9），保持状态 9
            next_V[9] = V[9];
            
            for (int j = 0; j < SIZE; j++) V[j] = next_V[j];
        }
    }

    cout << V[9] << endl; // 输出最终达成目标的方案数

    return 0;
}
```

### 关键点解析：
1.  **为什么 `V[0] = V[0]+V[1]+V[2]`**：井号不是字母。如果在井号前你只写了 `cc`（状态2），井号之后你再写个 `f` 已经不能构成 `ccf` 了，因为被井号隔开了。所以你的进度归零，重新变回“还没找到 ccf”的状态（状态0）。
2.  **为什么 `V[3] = V[3]+...+V[8]`**：同理，如果你已经写完了 `ccf`，但 `cspark` 写到一半（比如写了 `csp`，状态6），井号也会打断 `cspark` 的进度。但由于 `ccf` 已经在井号左侧存在了，你的进度只需要退回到“已有 ccf，寻找 cspark 开始”的状态（状态3）。
3.  **效率优化**：使用 `map` 缓存矩阵可以极大地减少计算量，因为 $m=10^6$ 时虽然段多，但很多长度（比如 0 或 1）会大量重复。
4.  **矩阵构建**：代码中的 `build_base_matrix` 准确模拟了一个字符串匹配自动机，考虑了所有可能的字母跳转。
